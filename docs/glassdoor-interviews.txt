# Alan — Retours d'entretiens (Glassdoor, Software Engineer)

Source : Glassdoor | 15 retours | Rôle : Software Engineer

---

## Synthèse des signaux clés

### Ce qui revient dans TOUS les refus
- Manque d'enthousiasme visible pour la mission santé (testé à chaque étape)
- Feature Design mal abordé : les candidats font du system design backend → Alan veut du product/user-centric
- Tests insuffisants pendant le live coding
- Pas de questions posées à Alan (ou questions trop génériques)
- Réponses écrites bâclées ou trop courtes

### Ce qui revient dans les retours positifs
- Feedback détaillé après chaque étape
- Exercices techniques proches du travail réel (pas d'algo puzzles)
- Interviewers bienveillants et accessibles
- Processus transparent sur ce qui est attendu

### Red flags mentionnés
- TypeScript recommandé même si le choix est libre ("type precision and naming conventions evaluated regardless of language")
- La feature design interview est un piège si abordée comme du system design classique
- Le niveau de compensation n'est révélé qu'à la fin du processus
- Questions écrites : 3-5 pages, pas de feedback donné dessus

---

## Étapes du processus (reconstituées depuis les retours)

1. **Screening — 30 min** — get to know each other, ~50% candidat pose des questions
2. **Questions écrites — async** — 4-5 questions, réponses 3-5 pages, pas de feedback donné
3. **Live coding — 1h** — CoderPad, exercice réel, TDD fortement valorisé, TypeScript recommandé
4. **Alaner Fit — 45 min** — Senior Alaner ou fondateur, checklist de valeurs, peu de place pour les questions candidat
5. **Pre-Alan Day call** — feedback avant le jour J, alignement compensation
6. **Alan Day — demi-journée**
   - Past Project — 1h — projet passé, décisions techniques, ce qu'on ferait différemment
   - Feature Design — 1h — feature sur whiteboard, user-centric pas backend-centric
   - Ask Me Anything — 30 min — pas noté, questions libres
   - Débrief — 15 min

## Questions réelles posées par Alan (compilées)

### Screening / Motivation
- Why did you choose Alan?
- Why would you want to work in healthcare?
- What would excite you about working in the healthcare industry?
- How would our culture allow you to thrive?
- What is your point of view about testing?
- What's your definition of a full-stack engineer?
- Is there a specific area where you have strong expertise worth exploring deeper?

### Comportemental / Fit
- What was a challenging situation and how did you resolve it?
- Tell me about a time you received difficult feedback. How did you handle it?
- How do you use AI to solve problems? Give an example where AI helped you improve efficiency or quality.
- Describe a past project and what made you make the decisions. What would you have done differently?

### Past Project (Alan Day)
- Describe a past project in detail.
- What decisions did you make and why?
- What would you have done differently?

### Feature Design (Alan Day)
- Implement a new feature on an existing system (user-centric approach expected, not pure backend)
- What does success look like?

### Technique (live coding)
- Implement a class/function on real-world data (CoderPad)
- Tests mandatory, TDD encouraged
- Code review questions
- Database concepts and concurrent access

## Lessons apprises des candidats refusés

1. **TypeScript > autre langage** même si le choix est libre — ils évaluent la précision des types
2. **Feature Design ≠ System Design** — ne pas parler d'infra, parler d'UX et d'impact member
3. **Poser des questions à Alan est obligatoire** — ne pas en avoir = signal très négatif
4. **Questions écrites = 3-5 pages** — traiter ça comme un vrai document Alan, pas comme un formulaire
5. **Mission santé** — testée à chaque étape, doit être sincère et spécifique à Alan (pas "j'aime la tech santé")
6. **TDD pendant le live coding** — écrire les tests en premier, pas après
7. **AI focus aide à passer** — mentionné explicitement dans un retour nov. 2025
